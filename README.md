# Study Assistant

An AI-powered study tool built for the Flam Frontend Internship Assignment. Paste your notes or a topic, and get back interactive flashcards and a quiz — generated by an LLM, but never shown as raw chat text.

**Live demo:** https://client-nine-eta-80.vercel.app/

## Features

- Free-form text input (notes or a topic)
- AI-generated flashcards (click to flip)
- AI-generated quiz with instant feedback (correct/incorrect highlighting)
- Score tracking and a "retry wrong answers only" flow
- Loading, error (with retry), and empty states
- Handles malformed/incomplete AI output without crashing
- Protects against stale responses overwriting newer ones
- Mobile responsive

## Tech Stack

- **Frontend:** React (hooks, functional components), Vite, plain CSS
- **Backend:** Node.js, Express
- **AI Provider:** Groq (`llama-3.3-70b-versatile`, OpenAI-compatible API, JSON mode)
- **Deployment:** Vercel (frontend)

## Architecture

```
React UI (client/) → Express backend (server/) → Groq API
                                                → Structured JSON
                                                → Server-side validation
                                                → Client-side validation
                                                → React state → Interactive UI
```

The Groq API key lives only on the backend (`server/.env` locally, or the host's environment variables in production) and is never exposed to the browser — the frontend only ever talks to the Express server.

## How the AI Integration Works

1. User submits free-form text via the input box.
2. Frontend sends `{ input }` to `POST /api/generate` on the Express backend.
3. Backend sends a strict system prompt to Groq, requesting JSON-only output matching a fixed schema (title, flashcards, quiz), using Groq's `response_format: json_object` mode.
4. Backend parses the raw text and validates its shape before responding.
5. Frontend independently re-validates the shape (including that each quiz answer is actually one of its own options) before rendering anything.
6. A request-id counter discards any response that isn't from the most recent request, preventing stale data from overwriting a newer result.

## Structured Response Format

```json
{
  "title": "string",
  "flashcards": [
    { "question": "string", "answer": "string" }
  ],
  "quiz": [
    { "question": "string", "options": ["string", "string", "string", "string"], "answer": "string" }
  ]
}
```

## Error-Handling Strategy

| Failure | Handled where | Result |
|---|---|---|
| Malformed JSON | Backend | 422, error state + retry |
| Wrong shape (missing/invalid fields) | Backend | 422, error state + retry |
| Quiz answer not in its own options | Frontend | Error state (backend "success" alone isn't trusted) |
| Empty AI response | Backend | 422, error state + retry |
| API/auth failure | Backend | 500, error state + retry |
| Timeout (15s) | Backend | 504, error state + retry |
| Stale/out-of-order response | Frontend (request-id guard) | Silently discarded; UI keeps the newest result |

The app is designed around the principle that **AI output is untrusted input** — nothing from the model reaches the UI without passing through parsing and shape validation on both the server and the client.
